# Helm Deployment of Static Web Server on OpenShift

## Objective

Deploy the `static-webserver` Helm chart to the OpenShift project:

```text
lab-customer-red
```

The application is exposed through an OpenShift Ingress and is accessible at:

```text
http://lab-static-webserver.apps.ocp4.example.com
```

---

## 1. Verify or Create the OpenShift Project

First, verify that the project exists. Create it only if it does not exist:

```bash
oc get project lab-customer-red || oc new-project lab-customer-red
```

Select the project:

```bash
oc project lab-customer-red
```

Expected result:

```text
Already on project "lab-customer-red"
```

---

## 2. Configure the Helm Values File

Edit the lab values file:

```bash
vi lab-customer-red.yaml
```

Example configuration:

```yaml
replicaCount: 2

image:
  repository: registry.ocp4.example.com:8443/redhattraining/hello-world-nginx
  tag: v1.0
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 8080

ingress:
  enabled: true
  className: openshift-default
  annotations: {}
  hosts:
    - host: lab-static-webserver.apps.ocp4.example.com
      paths:
        - path: /
          pathType: ImplementationSpecific

resources:
  limits:
    cpu: 250m
    memory: 512Mi

podLabels:
  stage: lab
  tag: latest

env:
  ENVIRONMENT: LAB
```

> **Note:** Do not configure a TLS Secret such as `chart-example-tls` unless that Secret exists or the task specifically provides certificate and key files.  
> Without a valid TLS Secret, expose the application by HTTP using the default OpenShift router.

---

## 3. Deploy the Helm Chart

From the chart directory, deploy the chart:

```bash
helm upgrade --install lab-static-webserver . \
  -n lab-customer-red \
  -f lab-customer-red.yaml
```

Example output:

```text
Release "lab-static-webserver" does not exist. Installing it now.
NAME: lab-static-webserver
NAMESPACE: lab-customer-red
STATUS: deployed
REVISION: 1
```

---

## Why Use `helm upgrade --install`?

The command:

```bash
helm upgrade --install
```

handles both installation and future updates.

| Release state | Result |
|---|---|
| Release does not exist | Helm installs it |
| Release already exists | Helm upgrades it |
| Values file is changed and command is rerun | Helm applies the updated configuration |

Using only `helm install` works for the first deployment, but it fails if the release name already exists.

---

## Why Use `-n lab-customer-red`?

The following options are equivalent:

```bash
--namespace lab-customer-red
```

```bash
-n lab-customer-red
```

Although the current OpenShift project is already `lab-customer-red`, explicitly specifying the namespace is recommended:

```bash
-n lab-customer-red
```

It ensures the Helm release is installed in the intended namespace, even if the currently selected project changes.

List Helm releases in the project:


Expected result:

```text

```

Check the Deployment, Pods, Service, and Ingress:

```bash

```

Expected resources include:

```text

ingress.networking.k8s.io/lab-static-webserver-lab-webserver
```

Verify the rollout:

```bash

  -n lab-customer-red
```

Expected result:

```text
deployment "lab-static-webserver-lab-webserver" successfully rolled out
```

## 6. Verify Labels and Configuration

Display labels:

```bash
oc get deployment,pods,service,ingress \
  -n lab-customer-red \
  --show-labels
```

Verify the Deployment configuration:

```bash

  -n lab-customer-red
```

Expected important settings:

```text

Port: 8080/TCP
CPU limit: 250m

tag=latest
```

---

## 7. Verify the Ingress

Check the Ingress:

```bash
oc get ingress -n lab-customer-red
```

Expected output:

```text
NAME                                 CLASS               HOSTS                                        ADDRESS
lab-static-webserver-lab-webserver   openshift-default   lab-static-webserver.apps.ocp4.example.com   router-default.apps.ocp4.example.com
```

The required Ingress class is:

```yaml
className: openshift-default
```

This OpenShift IngressClass uses the controller:

```text
openshift.io/ingress-to-route
```

---

## 8. Test Application Access

Test the application through the OpenShift router:

```bash
curl http://lab-static-webserver.apps.ocp4.example.com
```

Expected response:

```html
<html>
  <body>
    <h1>Hello, world from nginx!</h1>
  </body>
</html>
```

This confirms that the application is deployed successfully and reachable through the Ingress.
